Case Study

ERP Data Migration Clean-up (Excel VBA)

Each branch's everyday sales sheets, turned into one clean product list ready to import into Odoo ERP.

01

The Problem

Sheets built for selling, not for importing

Each of our four branches kept its own Excel sheets as a quick sales reference: check stock, quote prices and give customers part specifications. For that job they worked fine. But they were never built as a database: the same part was listed on more than one tab, often at different prices, names were typed in different ways, and some rows had no code or price.

When we moved to Odoo ERP, this data couldn't be imported as it was. It had to become one clean, reliable product list first, and there were over 10,000 unique products. Checking each one by hand would have taken far too long and missed our go-live deadline, so I automated it.

02

The Build

One click, rules agreed with the business

I built a VBA macro that cleans and combines every tab in one run. The rules came from the business, not from the code:

  1. Read every tab row by row, carrying the brand down from its header row.
  2. Never guess. A missing code or price goes to a review list for a person to check, because a guessed price silently corrupts reporting.
  3. Standardize names by trimming spaces and uppercasing, so “no101” and “NO101” are recognised as one part.
  4. Merge duplicates into one row, keeping the higher price.

Why VBA, not Power Query? The rules branch depending on the data, and the output goes into fixed places. Power Query is better suited to recurring file imports.

03

The Result

One click, from messy sheets to import-ready

Clicking Run Clean-Up does the whole job in one go: it reads every branch tab, cleans and merges the parts, sets aside anything that can't be trusted, and checks its own totals. A second button clears the output, so it can be re-run any time the sheets change.

MATCHCheck

Out of 68 raw rows, the macro outputs 52 clean records for Odoo, merges 11 duplicates using the pricing rule, and flags 5 rows for a person to check. A built-in reconciliation check confirms 52 + 11 + 5 = 68, so nothing ever disappears silently on the way into the new system.

The demo uses 68 rows; the real migration ran the same logic over more than 10,000 unique products across the four branches, in time for go-live.
